# データ入力ガイド

本ディレクトリは、プリセットの装備・道具・スキル・関係一覧・初期ストーリー・事前定義のパートナーアバター・事前定義のパートナー画像のデータを入力するためのものです。コードが分からない担当者でも簡単にメンテナンスできるようにしています。

ファイルは CDN 経由で読み込まれます。ページは自動的にタイムスタンプを付けてキャッシュをバイパスします。

## ファイル構成

```
public/assets/data/
├── README.md                # 本説明ドキュメント
├── baseInfo.json            # 基本情報データ（性別、種族、身分、初期場所）
├── equipments.json          # 装備データ
├── items.json               # 道具データ
├── skills.json              # スキルデータ
├── partners.json            # 関係一覧データ
├── backgrounds.json         # 初期ストーリーデータ
├── predefined-avatars.json  # 事前定義のパートナー初期アバター
├── predefined-partner-gallery.json  # 事前定義のパートナー画像
└── coreClassification.json  # コア分類データ（ランキング/グループ分け）
```

## JSON5 の特徴

本プロジェクトのデータファイルは JSON5 形式を使用しており、以下の機能をサポートしています：

1. コメントをサポート

   ```json5
   {
     // これは単行コメント
     "name": "道具名",
     /* これは複数行コメント
        何行でも書けます */
     "cost": 10
   }
   ```

2. 末尾カンマ（トレーリングカンマ）を許可

   ```json5
   {
     "name": "道具名",
     "cost": 10,  // 最後のプロパティの後にもカンマを付けられます
   }
   ```

3. より柔軟な文字列
   - シングルクォートを使用できる
   - 複数行の文字列をサポート

## クイックスタート

1. データファイルを直接編集する
   - `baseInfo.json`、`equipments.json`、`items.json`、`skills.json`、`partners.json`、`backgrounds.json`、`predefined-avatars.json`、`predefined-partner-gallery.json` を開く
   - フォーマットに従ってデータを追加・修正する
   - データの用途を説明するコメントを自由に追加できる

2. リポジトリにコミットする
   - 変更を GitHub リポジトリの `public/assets/data/` ディレクトリにコミットする
   - CDN が最新のデータファイルを自動的に同期する

## 重要なポイント

- コメントは自由に追加できる：`//` または `/* */`
- 末尾カンマは気にする必要はない：最後のプロパティの後にもカンマを付けられる
- ファイルごとのデータの内容：
  - `baseInfo.json` - 基本情報データ（性別、種族、身分、初期場所）
  - `equipments.json` - 装備データ
  - `items.json` - 道具データ
  - `skills.json` - スキルデータ
  - `partners.json` - 関係一覧データ
  - `backgrounds.json` - 初期ストーリーデータ
  - `predefined-avatars.json` - 事前定義のパートナー初期アバター
  - `predefined-partner-gallery.json` - 事前定義のパートナー画像。Destiny Tab のパートナー詳細の「画像」サブページに表示される
  - `coreClassification.json` - コア分類データ（ランキング/グループ分け）

## データ形式の説明

### 品質レベル (rarity)

データ内の rarity フィールドは品質レベルを表し、選択可能な値は以下の通りです：

- `common` - ノーマル
- `uncommon` - 優良
- `rare` - レア
- `epic` - エピック
- `legendary` - レジェンド
- `mythic` - ミシック
- `only` - ユニーク

**注意：このフィールドには中国語ではなく、対応する英語を入力する必要があります。**

### 装備データ (equipments.json)

```json5
{
  // 装備は分類ごとにまとめられています
  "剣類武器": [
    {
      "name": "精鉄の長剣",  // 装備名
      "cost": 12,            // 転生ポイントでのコスト
      "type": "武器",        // 装備タイプ
      "rarity": "common",    // 品質レベル
      "tag": ["片手剣", "攻撃: 18", "筋力+2"],  // タグ配列：[サブタイプ, 攻撃/防御: XXX, 属性+1/2]
      "effect": {  // 効果オブジェクト：キーが効果名、値が効果説明
        "攻撃強化": "追加で10ポイントの物理ダメージを与える",
        "筋力ボーナス": "筋力属性+2"
      },
      "description": "(装備の物語的な説明)",
    },
    // さらに装備を追加できます...
  ],
  "防具": [
    // 防具データ...
  ],
}
```

### 道具データ (items.json)

```json5
{
  // 道具は分類ごとにまとめられています
  "消耗品": [
    {
      "name": "治療薬",  // 道具名
      "cost": 5,         // 転生ポイントでのコスト
      "type": "消耗品",  // 道具タイプ
      "rarity": "uncommon", // 品質レベル
      "quantity": 1,    // 道具の数量（デフォルトは1）
      "tag": ["回復", "HP+50"],  // タグ配列（任意）
      "effect": {  // 効果オブジェクト：キーが効果名、値が効果説明
        "生命回復": "50ポイントの生命値を回復する"
      },
      "description": "(道具の物語的な説明)",
    },
  ],
}
```

### スキルデータ (skills.json)

skills.json の構造は1種類のみです。最外層は「分類」で、その下は配列です。「アクティブ/パッシブ」のような2層構造はありません。

```json5
{
  "戦技": [
    {
      "name": "強力斬撃",  // スキル名
      "cost": 15,          // 転生ポイントでのコスト
      "type": "アクティブ", // スキルタイプ
      "rarity": "rare",    // 品質レベル
      "tag": ["筋力", "単体", "物理攻撃", "威力: 150", "破甲"],  // タグ配列：[関連属性, 目標タイプ, 核心機能, 威力: XXX, 任意メカニズム]
      "consume": "[攻撃: 50SP]",  // コスト説明
      "effect": {  // 効果オブジェクト：キーが効果名、値が効果説明
        "強力斬撃": "150ポイントのダメージを与える。70%物理ダメージ、30%エネルギーダメージ",
        "破甲効果": "目標の20%の装甲を無視する"
      },
      "description": "(物語的な説明)",
    },
  ],
  // その他の分類：魔法、祈祷、その他...
}
```

### 基本情報データ (baseInfo.json)

```json5
{
  // 性別の選択肢
  "genders": ["男", "女", "雌", "雄", "ふたなり"],

  // 種族コストポイント（正数はポイントを減算し、負数は加算する）
  "raceCosts": {
    "ゴブリン": -10,
    "人間": 0,
    "獣族": 0,
    "翼民": 10,
    // さらに種族...
  },

  // 身分コストポイント
  "identityCosts": {
    "奴隷に落ちる": -20,
    "自由民": 0,
    "貴族階級": 40,
    // さらに身分...
  },

  // 初期場所
  "startLocations": [
    "大陸南東部-ソレンティス王国",
    "大陸北東部-ノースガルド連盟",
    // さらに場所...
  ]
}
```

注意：`baseInfo.json` の `genders`、`raceCosts`、`identityCosts`、`startLocations` には自動的に「カスタム」選択肢が追加されるため、手動で追加する必要はありません。

### 初期ストーリーデータ (backgrounds.json)

```json5
{
  "共通開始": [  // 初期ストーリーの分類
    {
      "name": "（初期ストーリータイトル）",  // 初期ストーリーを区別するためのタイトル
      "description": "（初期ストーリーの簡単な説明）",
      "requiredRace": "(種族)",  // （任意）選択に必要な種族
      "requiredLocation": "(初期場所)",  //（任意) 選択に必要な初期場所（startLocations に対応）
      "requiredIdentity": "(身分)",  // （任意）選択に必要な身分
    }
  ]
}
```

### コア分類データ (coreClassification.json)

コア分類データは、コアのグループ分けとランキング情報を定義するために使用します。各分類が1つの Tab として表示され、コアは同時に複数の分類に属することができます。

```json5
{
  // 分類名をキーとし、値はその分類のコアリスト
  "大杯": {
    // コア名（"命定システム-"プレフィックスと作者の括弧を含まない）
    "Aコア": {
      "note": "これは素晴らしいコアです", // コアの備考説明（任意）
    },
  },
}
```

**フィールドの説明：**

- 最外層のキー（例：`"大杯"`）：分類名で、Tab タグとして表示されます
- 2番目の層のキー（例：`"Bコア"`）：コア名で、ワールドブック内のコア名に対応している必要があります（`命定システム-` プレフィックスと末尾の作者括弧を含まない）
- `note`：（任意）コアの備考説明で、コアのボタンの下に表示されます

**特別な分類：**

- `特別おすすめ`：先頭に固定される Tab で、ハードコードされたおすすめコアに使用します（コード内で設定）
- `未分類`：未分類のコアのデフォルトグループで、末尾に固定されます

### 外部 NPC アバター、事前定義アバターとパートナー画像

Destiny Tab は、外部 EJS、外部スクリプト、リポジトリの事前定義ファイルから、NPC が関係一覧に入ったときのステータスバーのデフォルトアバターを読み込むことができます。デフォルトアバターは、ユーザーが手動でアバターを設定しておらず、明示的に削除もしていない場合にのみ有効になります。

#### セキュリティ制限

アバター URL とパートナー画像 URL は、以下の条件を満たす必要があります：

- プロトコルは `https` である必要があります
- ドメインは `files.catbox.moe`、`i.ibb.co`、`wsrv.nl` のみである必要があります
- ファイル拡張子は `.png`、`.jpg`、`.jpeg`、`.webp`、`.avif` のみである必要があります

ルールに適合しない URL は無視されます。

#### 外部 EJS による読み込み

最終的に書き込む必要がある `local`（スクリプト内の `chat` レベルに対応）変数のパスは以下の通りです：

```text
status.externalAvatars.partners.<NPC名>.url
```

参考コード：

```ejs
<%_
setLocalVar('status.externalAvatars.partners.<NPC名>.url', '<url>')
_%>
```

例：

```ejs
<%_
setLocalVar('status.externalAvatars.partners.水銀燈.url', 'https://files.catbox.moe/example.png')
_%>
```

#### 外部スクリプトによる読み込み

外部スクリプトは、アバター URL を chat 変数の完全なパスに書き込む必要があります：

```text
status.externalAvatars.partners.<NPC名>.url
```

例：

```json
{
  "status": {
    "externalAvatars": {
      "partners": {
        "アイリーン": {
          "url": "https://files.catbox.moe/example.png"
        }
      }
    }
  }
}
```

簡略形式はサポートされていません。`url` は文字列である必要があります。

#### 外部 EJS によるパートナー画像の読み込み

最終的に書き込む必要がある `local`（スクリプト内の `chat` レベルに対応）変数のパスは以下の通りです：

```text
status.externalGalleries.partners.<NPC名>.images
```

参考コード：

```ejs
<%_
setLocalVar('status.externalGalleries.partners.<NPC名>.images', [
  { title: '立ち絵', url: 'https://files.catbox.moe/example-1.png' },
  { title: '日常服', url: 'https://files.catbox.moe/example-2.webp' },
])
_%>
```

`images` は配列である必要があります。各エントリには `title` と `url` が必須です。

#### 外部スクリプトによるパートナー画像の読み込み

外部スクリプトは、画像リストを chat 変数の完全なパスに書き込む必要があります：

```text
status.externalGalleries.partners.<NPC名>.images
```

例：

```json
{
  "status": {
    "externalGalleries": {
      "partners": {
        "アイリーン": {
          "images": [
            {
              "title": "立ち絵",
              "url": "https://files.catbox.moe/example-1.png"
            },
            {
              "title": "日常服",
              "url": "https://files.catbox.moe/example-2.webp"
            }
          ]
        }
      }
    }
  }
}
```

URL 文字列だけの配列はサポートされていません。`title` と `url` はどちらも空でない文字列である必要があります。

#### リポジトリの事前定義アバター (predefined-avatars.json)

リポジトリ内でデフォルトアバターを管理することもできます：

```json5
{
  // key は関係一覧内のパートナー名と完全に一致している必要があります
  アイリーン: 'https://files.catbox.moe/example.png',
}
```

key は `関係一覧` 内の NPC 名と完全に一致している必要があります。value はセキュリティ制限を通過したアバター URL である必要があります。

#### リポジトリの事前定義パートナー画像 (predefined-partner-gallery.json)

Destiny Tab のパートナー詳細には「画像」サブページがあり、リポジトリ内でパートナー画像リストを管理できます。画像は MVU に書き込まれず、`<status_current_variables>` にも入りません。フロントエンドがパートナー名ごとに読み込んで表示するだけです。

```json5
{
  // key は関係一覧内のパートナー名と完全に一致している必要があります
  "アイリーン": [
    {
      "title": "立ち絵",
      "url": "https://files.catbox.moe/example-1.png",
    },
    {
      "title": "日常服",
      "url": "https://files.catbox.moe/example-2.webp",
    },
  ],
}
```

key は `関係一覧` 内の NPC 名と完全に一致している必要があります。value は画像エントリの配列である必要があります。配列内の各項目には `title` と `url` の両方を記入する必要があり、`url` はアバターと同じセキュリティ制限を受けるため、ルールに適合しないエントリは無視されます。

あるパートナーに画像が設定されていない場合、または設定後にすべての URL がセキュリティ制限で除外された場合、「画像」サブページには「画像がありません」と表示されます。

#### 優先順位

アバター表示の優先順位は、高い順に以下の通りです：

1. ユーザーがUI上でアップロードまたは保存したアバター
2. ユーザーが明示的にアバターを削除した後の空のアバター状態
3. chat 変数内のデフォルトアバター
4. リポジトリの事前定義アバター
5. システムのデフォルトプレースホルダーアバター

「アバターを削除」を行うと、chat 変数や事前定義アバターへのフォールバックが行われなくなります。「デフォルトに戻す」を行うと、ユーザーのローカルアバター記録がクリアされ、chat 変数や事前定義アバターが再度使用されます。

パートナー画像の表示優先順位は、高い順に以下の通りです：

1. chat 変数内のパートナー画像
2. リポジトリの事前定義パートナー画像
3. 空の状態

## 注意事項

1. JSON5 形式のヒント
    - 文字列はシングルクォート `'` またはダブルクォート `"` を使用できる
    - 数字には引用符は不要
    - 最後のプロパティの後のカンマはあってもなくてもよい
    - 句読点は中国語ではなく英語の記号を使用する
    - データの用途を説明するコメントを自由に追加できる

2. 装備/道具/スキルの必須フィールド
   - `name`：名前（空にできない）
   - `cost`：転生ポイントでのコスト（数字）
   - `type`：タイプ
   - `rarity`：品質
   - `tag`：タグ配列（例：`["タグ1", "タグ2"]`）
   - `effect`：効果オブジェクト（例：`{"効果名": "効果説明"}`）
   - `description`：説明

3. 特殊なフィールド
   - スキルデータには追加の `consume` フィールドが必要（コストの説明）
   - 道具データには追加の `quantity` フィールドが必要（数量、デフォルトは1）

4. 基本情報フィールド (baseInfo.json)
   - `genders`：性別の選択肢の配列
   - `raceCosts`：種族コストポイントのオブジェクト（正数はポイントを減算し、負数は加算する）
   - `identityCosts`：身分コストポイントのオブジェクト
   - `startLocations`：初期場所の配列

5. 分類名
   - 装備：剣類武器、防具、装飾品など
   - 道具：消耗品、素材など
   - スキル：戦技、魔法、祈祷、その他など

## よくある質問

**Q: データが反映されないのはなぜですか？**
A: 以下を確認してください：

1. ファイルが GitHub リポジトリに正常にコミットされていること
2. 技術担当者に連絡してバージョン番号を更新してもらうこと

**Q: JSON ファイルにコメントを書けますか？**
A: 書けます。本プロジェクトは JSON5 形式を使用しており、コメントを完全にサポートしています。`//` で単一行コメント、`/* */` で複数行コメントを書きます。

**Q: 最後のプロパティの後のカンマは削除すべきですか？**
A: 削除する必要はありません。JSON5 は末尾カンマをサポートしているため、残しても削除しても構いません。

**Q: 新しい分類を追加するにはどうすればよいですか？**
A: 対応するファイルで既存のフォーマットに従って新しい分類名とデータを追加するだけです。分類の用途を説明するコメントを追加することをお勧めします。

その他の問題がある場合は、技術担当者にご連絡ください。
